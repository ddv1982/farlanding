# Audio provenance

Every sound effect, ambience bed, Advisor phrase, sting and piece of music in Farlanding is
generated by the Python scripts in `audio_src/`. They build it from oscillators (sine, soft saw
and square, FM, additive wavetables written as harmonic lists in the recipe), seeded noise
(white, pink, brown), envelopes, filters, delays, and reverb whose impulse responses are
themselves generated from seeded noise. The "instruments" in `audio_src/synth/instruments.py`
(marimba, chime, bell, reed, pad voice) are modal or additive models made of those same parts.

- **No samples, recordings or third-party audio.** Nothing is recorded, downloaded, sampled,
  traced or licensed. There are no soundfonts, sample libraries, recorded impulse responses,
  MIDI files or presets.
- **No external services.** Nothing generates audio over a network, and no AI audio models are
  used.
- **No paid tools.** Everything used is free and open source (below).

Each manifest entry records the same thing in its `source` field: *synthesised (audio_src
recipes); no recordings, samples or external services*.

## What the build reads

Checked by searching `audio_src/` (Phase 9) for any file, network or audio input: `open`,
`read`, `load`, `np.load`, `np.fromfile`, `scipy.io`, `wavfile`, `soundfile`, `urllib`,
`requests`, `socket`, `http`, `.wav`, `.ogg`, `.flac`, `.mp3`, `.sf2`, soundfont and sample
library names. Every match is one of these:

| Read | Where | What |
|---|---|---|
| The files the build has just written | `build.py: analyse` via `synth/io.py: read_wav` / `read_any` | the analysis judges each file as the game will load it (an Ogg is decoded again with ffmpeg) |
| `audio_src/manifest.json` | `build.py` | the previous manifest (only with `--only`, to keep the other entries) and the hashes for `--check` |
| `game/assets/audio/**/*.import` | `build.py: write_import` | to keep the uid Godot assigned when import settings are rewritten |
| `game/data/sounds/**/*.tres` | `build.py: scaffold_events` | only to see whether an event exists already (existing ones are never overwritten) |

`audio_src/` has no other files: the only non-Python file in it is `manifest.json`. No recipe
reads anything. Every recipe is a function `(rng) -> samples`, and its random generator is seeded
from a CRC-32 of the sound's id (`recipes/__init__.py`).

**Result: every audio file in `game/assets/audio` is generated purely by synthesis.** The 601
`.wav` and `.ogg` files there correspond one to one to the 601 manifest entries, and each one
re-renders to the same bytes (below).

## Rebuild every asset

From the repository root:

```sh
uv run --python 3.12 --with numpy==2.5.4 --with scipy==1.18.1 audio_src/build.py
```

This renders all 601 sounds into `game/assets/audio`, rewrites `audio_src/manifest.json`
(id, file, recipe, seed, format, length, loudness, true peak, SHA-256) and the `.import`
settings, and fails if any file clips, misses its loudness target, has DC offset, breaks its
length bounds, has an audible loop seam, or (Ogg) falls below the codec fidelity floor. It takes
about 5 minutes. `--only SUBSTRING` renders just the sounds whose id contains the substring.

## Verify against the manifest

```sh
uv run --python 3.12 --with numpy==2.5.4 --with scipy==1.18.1 audio_src/build.py --check
```

`--check` renders every recipe into a temporary directory and compares each file's SHA-256 with
the manifest and with the file on disk. It writes nothing in the repository, and it exits
non-zero if any file differs or the manifest names a sound that no recipe makes. (A full build
followed by `git status game/assets/audio audio_src/manifest.json` shows the same thing.)

**Determinism.** Rendering is bit-exact. Every random draw comes from a seeded generator,
including the WAV dither, and the Ogg encoder runs with metadata stripped and bit-exact flags.
Phase 9 checked this: a full build reproduced every committed file byte for byte except the ones
whose recipes had changed, and `--check` afterwards reported 601 of 601 identical. The hashes
depend on the pinned versions above. A different NumPy or SciPy can change floating-point
rounding, and a different FFmpeg can change the Ogg bytes (WAV files are written by Python's
own `wave` module). If you upgrade one, rebuild, listen, and commit the new manifest.
